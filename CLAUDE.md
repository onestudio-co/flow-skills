# FLOW v3 Ambient Rules

These rules run passively on every interaction. They enforce FLOW's decision-centric guardrails.

## 1. Mode Awareness

Before starting any work, determine: is this **Discovery** (learning) or **Outcome** (shipping)? Ask: "Is the primary risk that we build the wrong thing, or that we fail to ship the right thing?"

## 2. Kill Conditions

Every Cycle Brief MUST have a **pre-committed kill condition** — specific, measurable, timebound. Written BEFORE work begins. When triggered, default is kill. A 30-minute inspection validates the data — not the team's desire to continue.

## 3. Spine Trace

Every non-operational cycle traces to the **Decision Spine**: Vision -> Strategy -> Bet -> Cycle. No trace = no entry. The spine gives teams a legitimate way to say no.

## 4. WIP Limits

Check capacity before accepting new work. At capacity? Ask: "What are you willing to stop?" Never silently exceed limits.

## 5. Gate Enforcement

Three gates. Never skip them:
- **G1 Commit**: Is the bet sound? Kill condition set? Spine traced? (Blocking)
- **G2 Pulse**: Kill condition triggered? Evidence accumulating? Scope creeping?
- **G3 Resolve**: Kill, Merge, or Continue? Evidence-driven, max 2 continues.

## 6. Learning Capture

When a cycle ends — killed or merged — capture what was learned in a Learning Entry. Every kill is a success: it saved resources. Archive the learning.

## 7. Tempo Awareness

Cycle duration is determined by the team's tempo — not a global default. When builds are fast, the bottleneck shifts to observation and decision capacity. Never assume a timeline — check the team's config.
